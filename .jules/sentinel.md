## 2024-05-15 - [Mass Assignment and IDOR in FastAPI Pydantic Models]
**Vulnerability:** The `MensagemUpdate` schema allowed mass assignment of `remetente` (sender), `destinatario` (recipient), and `horario` (timestamp). Additionally, `update_mensagem` and `delete_mensagem` handlers permitted any participant of a conversation to modify or delete a message, which is an Insecure Direct Object Reference (IDOR) since a recipient shouldn't be able to alter the sender's content or delete it globally.
**Learning:** Pydantic models blindly bind input data to all defined fields unless restricted. Role-based checks like "is participant" are insufficient for operations that strictly require ownership (like editing/deleting a sent message).
**Prevention:** Always restrict Update schemas to only the fields that are safe to be user-modified (e.g., `texto` only). Validate that the `current_user` explicitly matches the `remetente` (author) for destructive or edit actions, not just any participant.
