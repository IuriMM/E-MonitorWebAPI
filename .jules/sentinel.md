## 2024-05-24 - Mass Assignment and Broken Access Control on Mensagem Updates
**Vulnerability:** The `MensagemUpdate` model allowed users to modify the sender (`remetente`), recipient (`destinatario`), and timestamp (`horario`) of a message, enabling mass assignment spoofing. In addition, the edit and delete endpoints for messages in `routes/mensagens.py` only checked if the current user was a participant in the conversation, incorrectly allowing recipients to edit or delete messages sent to them (Broken Access Control/IDOR).
**Learning:** The previous implementation conflated "participant in a conversation" with "owner of a message resource." Also, Pydantic update models must explicitly exclude fields that shouldn't be mutable after resource creation.
**Prevention:** Always restrict update/delete permissions strictly to the resource author/owner unless higher-privileged roles (like admins) are involved. Expose only the fields intended to be modified in Update Pydantic models.
