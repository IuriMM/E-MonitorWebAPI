## 2023-10-27 - IDOR in Update Endpoints
**Vulnerability:** Insecure Direct Object Reference (IDOR) / Missing Ownership Check in the `PUT /duvidas/{id}` endpoint. An authenticated user could update any other user's doubt because the endpoint did not check if the current user was the owner of the resource being updated.
**Learning:** Sometimes ownership checks are correctly implemented in destructive endpoints like `DELETE` but missed in `PUT` / `PATCH` endpoints. We must enforce ownership checks on all endpoints that modify a resource, retrieving the existing resource before applying the update.
**Prevention:** Always retrieve the entity from the database and verify the `current_user` matches the entity owner (or has the appropriate admin/monitor roles) *before* processing the update payload.
## 2023-10-02 - Message Ownership Authorization Bypass & Mass Assignment
**Vulnerability:** In `routes/mensagens.py`, the PUT and DELETE endpoints for messages allowed any participant in a conversation (sender or recipient) to modify or delete a message. Additionally, `models/mensagens.py` allowed `MensagemUpdate` to modify the `remetente` (sender) and `destinatario` (recipient) fields.
**Learning:** This occurred because the authorization check reused the read access logic (`current_user["nome"] in (mensagem["remetente"], mensagem["destinatario"])`) for write operations, failing to enforce strict ownership. The lack of field restriction in the update model exacerbated this by allowing recipients to forge message details. Read operations can allow access to multiple parties (e.g., all participants in a thread), but write operations must restrict access to the specific owner/author of the resource.
**Prevention:** Always differentiate authorization logic between read and write operations. Implement strict ownership checks (`current_user["nome"] == resource["autor"]`) for updates and deletions, unless administrative overrides apply. Use tailored Pydantic models for update operations to omit fields that must be immutable after creation.
